# 第一期 Agent 接入验收

验收日期：2026-10-10（北京时间）。范围对应 [Issue #3](https://github.com/aihuanxi/FlowBot/issues/3)。

设备：一台 OPPO Android 12 真机，企业微信 5.0.11；独立版 APK 0.2.0（versionCode 2）。服务：北京区 2 vCPU / 2 GiB Ubuntu 24.04，Python 标准库后端；通用接收示例是同机独立 HTTPS 进程和 SQLite 数据库。真实通信对象为用户授权的测试联系人。

## 真实主链路

旧固定关键词规则已移除，接收配置改为独立订阅。验收中由 Codex 通过 HTTP 读取 Webhook 接收端的真实事件，理解后调用 `/events/<event_id>/reply`。发送动作均由 APK 的 AccessibilityService 完成，没有用 ADB 点击或输入企业微信。

| 真实来信 | 接收来源 | Agent 处理 | 结果 |
| --- | --- | --- | --- |
| 今天是哪一天？ | 前台无障碍界面 | 回答 2026 年 10 月 10 日、星期六 | Webhook HTTP 200，任务 succeeded，用户确认收到 |
| 连续消息测试（第 1 条） | 前台无障碍界面 | 确认第 1 条已接收 | 独立事件 ID，任务 succeeded，用户确认收到 |
| 连续消息测试（第 2 条，同一正文） | 前台无障碍界面 | 确认第 2 条已接收 | 与第 1 条不同 ID，任务 succeeded，用户确认收到 |
| 你现在能做什么？ | 后台通知 | 根据当前能力说明私聊文字接收、Agent 判断及主动发送 | Webhook HTTP 200，任务 succeeded，用户确认收到 |

前台日期消息事件 `38d5c1410b3df6e71f9223121d74641d6b36b336f810732599a88789f2db4e5c`，回复任务 `ba1eb84d-e2d8-4463-8931-b650417ef426`。相同正文再次调用回复接口仍返回这个已成功任务，没有新建任务。

两条连续消息及后台能力提问期间，故意停止 Webhook 接收端。三条事件仍在后端持久化，交付状态为 `retry`。随后重启主后端并恢复接收端，三条原事件分别在第 7、7、6 次尝试完成 HTTP 200 交付，每个事件在接收端仅落库一次，再由 Agent 创建回复任务。交付恢复允许乱序，Agent 按接收时间整理这组上下文。

验收结束：主后端共保留 6 条事件（此前 2 条、本期 4 条）、8 条任务（此前 4 条、本期 4 条）；本期 4 条交付全部 `delivered`，接收端 4 条唯一事件。没有把打开会话时的旧历史或自己的 4 条回复录成新入站事件。手机上报 0.2.0，两项权限和解锁状态正常。

- 10 个后端真实 HTTP 行为测试通过：认证、设备隔离、发送幂等、任务提交后才确认 HTTP、并发领取、订阅、增量读取、事件回复、回调去重、重启恢复、Webhook 失败重试、接收端冲突及重启持久化、不跟随重定向。
- 8 个通知正文解析断言及 8 个前台增量断言通过，包括相同文字的新行、滑动窗口、初次基线和自身消息锚点。
- release APK 构建与 Lint 通过；`apksigner verify` 通过，包为 0.2.0 且不可调试。
- Python 编译、Shell 语法、OpenAPI JSON/引用、Skill frontmatter及文档相对链接检查通过。
- 公网 HTTPS API 和独立接收端认证有效，未认证接收端返回 401。

## 验收边界

只验证一台手机、明确联系人和以上消息序列。此前主动推送「你好」已由用户确认，相关发送 API 未改变。本期没有验收 10 台真机容量、48 小时持续运行、手机重启、完整断网或省电杀进程。界面选择器和前台增量依赖已校准版本，首次进入及断开的可见窗口不会补抓历史；通知与界面缺乏官方消息 ID，全部跨来源切换场景的唯一性未获保证。IP 自签名证书需要操作员到期前更新。Agent 的长期运行和唤醒由使用方安排，通用接收端只持久化事件，不运行模型。
